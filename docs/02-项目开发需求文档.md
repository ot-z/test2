## 1. 引言

### 1.1 编写目的

把原始方案中口语化的设想，转化为**可评审、可开发、可测试、可验收**的需求基线，作为后续设计、编码、测试与版本回退的依据。本文档一经批准，功能变更需走变更记录并同步更新版本号。

### 1.2 范围

**范围内**：本地单机运行的刷题学习助手，覆盖题目目录管理、知识点与大纲体系、每日计划与间隔复习、学习记录与思路笔记、DeepSeek 驱动的题目分析与代码诊断、文档导出、系统设置、版本与数据管理。

**范围外**（本期明确不做）：在线判题与代码提交、账号与多用户、云端同步与移动端、题目全文/样例/官方题解的抓取与存储、社区题解、付费题库内容、商业化发布。

### 1.3 术语表

| 术语     | 定义                                      |
| ------ | --------------------------------------- |
| 题目元信息  | 来源、题号、标题、难度、标签、原题链接；**不含**题面、样例、测试数据、题解 |
| 新题     | 当日首次学习、尚未进入复习池的题目（学习方式以研读题解为主）          |
| 复习题    | 已学满 `review_delay_days` 天、被调度到当日重做的题目   |
| 知识点节点  | 知识点树中的一个节点，分属「知识点 / 数据结构 / 算法」三类之一      |
| 大纲     | 目标赛事的知识点清单与难度系数，以版本化 YAML 配置维护          |
| 候选题单   | 由大纲自动生成的待确认题目序列，确认后才写入每日计划              |
| 每日计划快照 | 生成当日即固化的任务清单，不随题库后续变更而改变                |
| AI 建议  | 大模型输出的内容，未经人工确认不得写入正式题解或作为正确答案展示        |

## 2. 项目概述

### 2.1 背景与目标

用户长期备战蓝桥杯一类算法竞赛，需要持续刷题与学习数据结构。当前痛点是「找题、定顺序、安排复习」三件事消耗额外精力。本项目目标：

- **G1** 把「今天该学哪道新题、该复习哪道旧题」变成打开页面即可看到的清单，无需人工决策。
- **G2** 把每次刷题的思路、代码、AI 分析沉淀为可检索、可导出的个人知识资产。
- **G3** 用大模型降低「看不懂题解」「找不到代码错在哪」的时间成本。
- **G4** 全部数据本地持有，版本可回退，长期可用、不依赖第三方服务存活。

### 2.2 用户与使用场景

单一用户（项目所有者），Windows 11 本机，浏览器访问 `http://127.0.0.1:<port>`。典型一天：

1. 打开首页 → 看到今日 1 道新题 + 1 道复习题（含原题外链）。
2. 点外链跳到 OJ，研读题解 / 重做题目。
3. 回到本地页面，标记完成状态、写下思路总结（Markdown，可贴代码）。
4. 遇到卡点，用 AI 分步提示或粘贴代码做诊断。
5. 需要复盘时，选定日期范围一键导出 Markdown 文档。

### 2.3 运行环境与约束

| 项    | 约定                                                |
| ---- | ------------------------------------------------- |
| 操作系统 | Windows 11（macOS / Linux 不作要求，但不主动绑定 Windows API） |
| 运行时  | Python 3.13（后端）；Node 22 可选（仅前端构建时需要）              |
| 数据库  | SQLite 单文件，位于 `data/`，**不纳入 git**                 |
| 网络   | 仅「题库同步」「DeepSeek API」需要联网；核心闭环离线可用                |
| 监听   | 仅 `127.0.0.1`，不对外暴露端口                             |
| 用户数  | 1，无登录鉴权                                           |
| 合规约束 | 不抓取、不存储第三方题面/样例/题解；遵守 `robots.txt`；外部请求限速 ≥ 1 秒   |

### 2.4 关键假设

- A1：用户接受「不自动抓题面」，AI 分析所需题面由用户粘贴或本地文件导入。
- A2：大纲为本地可编辑配置，每年由用户手动更新一次。
- A3：DeepSeek API Key 由用户自行申请并承担费用；项目提供用量记录。
- A4：复习规则按第 4.3 节参数化实现，参数变更只影响新生成的计划，不回溯历史。

## 3. 总体设计

### 3.1 逻辑架构

```
┌─────────────────────────── 表现层（本地浏览器） ───────────────────────────┐
│ 今日任务 · 题库目录 · 知识点树 · 大纲/题单 · 记录与笔记 · AI 面板 · 设置 · 导出 │
└──────────────────────────────────┬───────────────────────────────────────┘
                                   │ HTTP / JSON / SSE
┌──────────────────────────────────▼───────────────────────────────────────┐
│ 应用层                                                                     │
│ PlanService   RecordService   NoteService   AiService   ExportService       │
│ SyncService   SyllabusService SettingsService                              │
├───────────────────────────────────────────────────────────────────────────┤
│ 领域层                                                                     │
│ ProblemCatalog · KnowledgeTree · TagMapper · ReviewScheduler               │
├───────────────────────────────────────────────────────────────────────────┤
│ 适配层                                                                     │
│ CodeforcesAdapter · AtCoderAdapter(可选) · ManualImporter · DeepSeekClient  │
├───────────────────────────────────────────────────────────────────────────┤
│ 存储层                                                                     │
│ SQLite（业务数据） · YAML（大纲/标签映射） · .env（密钥，不入库） · 导出目录   │
└───────────────────────────────────────────────────────────────────────────┘
```

**设计约束**：表现层只消费 JSON API；即便 M1 采用服务端渲染页面，后端接口契约也需先行定义，以保证后续更换前端不改后端。

### 3.2 技术选型

| 层        | 选型                                               | 说明                    |
| -------- | ------------------------------------------------ | --------------------- |
| 后端       | Python 3.13 + FastAPI + Uvicorn                  | 采集、AI、文档生成生态最完整       |
| ORM / 迁移 | SQLAlchemy + Alembic                             | 所有 schema 变更可升级 / 可降级 |
| 页面       | Jinja2 模板 + HTMX（少量原生 JS）                        | 零构建、单语言（方案 B，见 D-17）  |
| 数据库      | SQLite（WAL 模式）                                   | 单文件、零运维、易备份           |
| HTTP 客户端 | `httpx`                                          | 数据源同步，统一限速与重试         |
| AI SDK   | `openai`（配置 `base_url=https://api.deepseek.com`） | 官方 OpenAI 兼容模式        |
| 配置       | `python-dotenv` + YAML                           | 密钥与大纲分离               |
| 版本管理     | Git                                              | 见第 9 节                |

## 4. 功能性需求

> 优先级：**P0** = M1 必须有；**P1** = M2/M3；**P2** = M4 或可选。每条「验收标准」均为可测条件。

### 4.1 题目目录（M-Catalog）

**FR-01 题目元信息维护**（P0）

- 描述：支持手工新增、编辑、停用题目；字段包含来源（`codeforces` / `luogu` / `leetcode` / `atcoder` / `lanqiao` / `other`）、原题号、标题、原题 URL、原始难度、归一难度（1–5）、外部标签、备注。
- 主流程：新增时以 `(source, source_key)` 做唯一性校验，重复则提示并跳转已有记录。
- 验收：新增一条记录后列表可见；同一来源同一题号重复新增被拒绝；点击标题可在新标签页打开正确的原题 URL。

**FR-02 批量导入**（P0）

- 描述：支持粘贴题号列表或导入 CSV，批量创建题目元信息；不联网抓取题面。
- 验收：粘贴 20 行题号可一次创建 19 条（1 条重复被跳过并给出清单）；导入失败不产生半写入数据。

**FR-03 题目筛选与检索**（P0）

- 描述：按知识点、数据结构、算法、难度档、来源、是否已学组合筛选；支持标题/题号模糊搜索。
- 验收：5000 条题目数据下筛选响应 < 300 ms；结果可分页。

**FR-04 数据源同步**（P1）

- 描述：M-Sync 通过适配器拉取**官方公开 API** 的元信息，增量写入题目表；不覆盖人工编辑过的字段；记录同步日志。
- 数据源策略：
  - Codeforces 官方 API — 允许自动同步；
  - AtCoder Problems 公开 JSON — 可选，访问间隔 ≥ 1 秒，缓存兜底；
  - 洛谷 / LeetCode / 蓝桥杯 — **禁止自动抓取**；按需补题走 FR-27（浏览器内单题总结）或 FR-01/FR-02 手工录入。
- **本期边界（对应 D-20 决策）**：M1–M4 **不实现** HTML 题目页抓取、自动批量翻页/遍历列表、绕过 Cloudflare 或验证码、复用登录 Cookie 无人值守采集，也不调用 LeetCode 被 `robots.txt` 禁止的 `/api/`、`/graphql` 端点；不批量存储第三方题面/样例/题解原文。HTML 页面爬取**保留为待评估风险项 RK-09**，未来如需放开须重新核查 `robots.txt`、服务条款与版权并经单独评审。
- 异常：接口失败或改版时保留既有目录、标记 `sync_status=stale` 并在界面提示，不得清空本地数据。
- 验收：断网执行同步不报错崩溃、不丢数据；同步后人工修改过的标题不被覆盖；代码中不存在 HTML 页面解析逻辑。

### 4.2 知识点、标签与大纲（M-Knowledge / M-Syllabus）

**FR-05 知识点树**（P0）

- 描述：树形结构，节点含名称、类别（知识点 / 数据结构 / 算法）、父节点、排序；支持增删改与层级调整。
- 验收：能建立至少两层结构；删除父节点时子节点处理方式明确（阻止删除或一并迁移，需在实现前确认，默认阻止）。

**FR-06 标签映射与难度归一**（P0 / P1 自动标注）

- 描述：`tag_mappings` 把外部标签映射到内部知识点节点；各来源配置难度分段规则，统一为 5 档。P1 增加 AI 辅助标注。
- 验收：Codeforces 的 `dp` 经映射后出现在「动态规划」节点下；同一题目可挂多个节点；AI 建议的标签带 `confidence=ai` 且默认未确认，确认前不参与组题筛选。

**FR-07 大纲版本管理**（P0）

- 描述：以 YAML 维护大纲（名称、赛项、组别、版本、生效日期、来源 URL、知识点清单、难度系数区间、优先级），界面可查看与编辑。
- 验收：内置一份蓝桥杯软件赛基线大纲；新增一个大纲版本后，旧版本题单不受影响。

**FR-08 候选题单生成**（P0）

- 描述：选定大纲版本 + 难度区间 → 过滤未学题目 → 按知识点优先级/通过率排序 → 生成候选题单；支持预览、剔除、拖拽调序、确认。确认后的顺序作为后续每日「新题」的取题队列。
- 验收：生成的题单不含已学题目；人工剔除的题不再出现在计划中；确认前不写入 `daily_plans`。

### 4.3 每日计划与复习调度（M-Plan）—— 核心需求

**FR-09 计划参数配置**（P0）

- 参数：`new_per_day`（默认 1）、`review_per_day`（默认 1）、`review_delay_days`（默认 7）、`review_repeat`（默认 1，即每题只复习一次）、`selection_strategy`（默认 `earliest_due`）、`start_date`、每周休息日、暂停日期区间。
- 验收：参数修改仅影响**之后生成**的计划，历史计划快照不变；参数持久化到 SQLite。

**FR-10 每日计划生成**（P0）

- 规则（严格对应原始方案）：
  1. 自 `start_date` 起第 1–7 天：每天仅 `new_per_day` 道新题，无复习题。
  2. 第 8 天起：每天 `new_per_day` 道新题 + `review_per_day` 道复习题。
  3. 复习题从「已学满 `review_delay_days` 天、且复习次数未达 `review_repeat`」的题目中按 `selection_strategy` 选取。
  4. 新题从 FR-08 确认的题单队列按序取用；队列耗尽时计划标记为「题单不足」而非随机补题。
- 验收：以 `start_date=2026-11-09` 生成 14 天计划 → 第 1–7 天各 1 项，第 8–14 天各 2 项（1 新 + 1 复习），且第 8 天的复习题正是第 1 天的新题；同一天重复生成不产生重复任务。

**FR-11 任务状态流转**（P0）

- 状态机：`pending → learning → learned(已学题解) → ac(独立通过) → reviewed(已完成复习)`；任意状态可 `skipped`。
- 只有达到 `learned` 及之后状态的题目才进入复习池。
- 验收：把第 1 天任务标为 `skipped` 后，该题不进入后续复习池；状态变更写入操作时间，可追溯。

**FR-12 漏打卡与暂停**（P0）

- 规则：**顺延不堆积**。当日未完成项保留在历史中标记 `skipped/overdue`，次日不追加补偿任务（对应 D-07 默认值）。暂停区间内不生成任务。
- 验收：连续 3 天不打卡后，第 4 天任务数仍为「1 新 + 1 复习」，不出现 4 项积压。

**FR-13 动态复习（可选增强）**（P2）

- 支持 SM-2 简化版：复习后打分 1–5，动态更新 `interval_days` / `ease_factor` / `repetition`；可在设置中于「固定节奏」与「动态间隔」间切换。
- 约束：M1 数据表必须预留上述字段，接入时不得改表。

### 4.4 学习记录与笔记（M-Record）

**FR-14 学习记录**（P0）

- 每条任务可记录：完成结果、耗时（分钟）、语言、代码片段、自评掌握度（1–5）、备注。
- 验收：保存后刷新页面数据不丢失；记录与对应任务、题目关联正确。

**FR-15 思路总结笔记**（P0）

- Markdown 编辑器，支持代码围栏与语法高亮、防抖自动保存、保存状态提示；一题可有多篇笔记。
- 验收：断网状态下编辑并保存成功；重新打开还原内容；导出的 Markdown 中代码块格式正确。

**FR-16 历史与统计**（P0 / P2）

- P0：按日 / 按题 / 按知识点三种视图回看历史，支持时间范围筛选。
- P2：连续打卡天数、累计题量、知识点覆盖热力图、难度分布。
- 验收：日历视图能看到每一天的计划项与实际完成状态。

### 4.5 AI 智能体（M-AI，M3）

**FR-17 模型与参数配置**（P1，框架 P0）

- 设置项：模型 ID（**预设下拉 + 自定义输入框**，不得硬编码枚举）、API Key、base_url、temperature、max_tokens、`thinking` / `reasoning_effort`、超时、重试次数、流式开关。
- 预设值：`deepseek-flash`（默认）、`deepseek-v4-pro`；**已停用的 `deepseek-chat` / `deepseek-reasoner` 不得作为默认值**，若用户手填需在保存时提示风险。
- 参数按模型能力白名单校验；不支持的参数禁用并给出说明（如 `frequency_penalty` / `presence_penalty` 被服务端忽略）。
- API Key 写入 `.env.local`（gitignore 排除），界面仅显示掩码；日志中不得出现完整密钥。
- 验收：填入自定义模型 ID 后调用成功；切换模型后参数面板随之变化；服务返回 402 时界面提示「余额不足」，429 时自动退避重试。

**FR-18 题目分析**（P1）

- 用户粘贴题面/思路 → 输出「考察知识点 → 解题思路分步提示 → 复杂度分析 → 参考代码（默认折叠）」。
- 默认以分步提示为主，避免直接给答案；所有输出标注「AI 生成，仅供参考」。
- 验收：流式输出（SSE）逐段显示；中断生成不留半截脏数据；输出关联到题目并可被导出文档引用。

**FR-19 代码诊断**（P1）

- 用户粘贴代码 + 错误现象 → 输出错误定位、原因分析、修改建议；不得自动改写用户已保存的代码。
- 验收：返回内容包含具体行号或代码片段定位；原始代码保持不变。

**FR-20 标签建议**（P1）

- 用 JSON 模式输出候选知识点/难度；结果写入 `confidence=ai` 且 `verified=false`，人工确认后才生效。
- 验收：模型返回非法 JSON 时降级为「解析失败，可重试」，不写入脏标签。

**FR-21 用量记账**（P1）

- 记录每次调用的模型、prompt/completion token、估算费用、时间、场景；设置页可查看累计。
- 验收：调用后记录可见；导出报告中可选包含 AI 分析摘要。

### 4.6 导出（M-Export）

**FR-22 Markdown 导出**（P0）

- 选择日期范围（起止日期、可选是否包含 AI 分析、是否包含代码片段）→ 生成一份结构化 Markdown 复盘文档，含：概览统计、按日分节（新题 / 复习题 / 完成状态 / 思路总结 / 代码片段 / AI 摘要）、题目外链清单。
- 验收：导出文件用 UTF-8 编码、可被任意 Markdown 编辑器打开；空日期范围生成空报告并提示，不报错；导出物默认不纳入 git。

**FR-23 PDF / DOCX 导出**（P2）

- 通过 Pandoc / Typst / python-docx 扩展；需明确引入依赖前评估体积与安装成本。

**FR-24 数据快照**（P0）

- 一键导出全量业务数据为 JSON（题目、知识点、计划、记录、笔记），用于备份与迁移；支持从快照导入。
- 验收：导出 → 清空库 → 导入，数据条数与关键字段一致。

### 4.7 设置与系统

**FR-25 设置管理**（P0 框架）

- 集中管理计划参数、AI 参数、数据源开关、导出目录、界面偏好；所有配置有默认值与重置入口。

**FR-26 健康检查与错误提示**（P0）

- 首页显示：数据库连接状态、题单剩余量、AI 配置状态（未配置/已配置/不可用）、最近一次同步结果。
- 验收：AI 未配置时核心页面仍可正常使用，仅 AI 面板给出引导。

**FR-27 浏览器内单题总结与导入**（P1，**D-18 已确认：载体 B**）

- 描述：**采用会话式工作流**。由 AI 助手用浏览器能力打开站点、按需搜索并总结若干题目，产出符合附录 C 契约的结构化 JSON/CSV（题号、标题、来源、链接、知识点、难度建议、摘要），用户确认后经 FR-02 导入题库；**项目内不含任何采集代码**。
- 载体 A（浏览器扩展 / 书签脚本把当前页正文 POST 到本地服务）**不属于本期范围**，仅作为 M4 可选增强保留。
- 约束：仅处理用户主动发起的单页 / 按需任务；不自动遍历列表、不绕过反爬、不复用登录态做无人值守采集；AI 建议的标签与知识点以 `verified=false` 入库，人工确认后才参与组题。
- 单题题面原文按 **FR-28** 单独通道处理，不混入本导入文件。
- 验收：导入 10 条结构化题目记录后题库可见且外链可跳转；文件格式错误时给出可读提示且不产生半写入；题库中不存在题面原文批量字段。

**FR-28 单题题面本地快照**（P1，**D-19 已确认**）

- 描述：允许用户主动为**单道题**保存题面原文快照，写入 `problem_snapshots` 表（`id`、`problem_id`、`content_md`、`source_url`、`captured_at`、`user_initiated`）。
- 边界：仅本地 SQLite；**不参与 FR-22 文档导出**、不进入任何对外分享内容、不由批量导入自动生成；界面标注来源 URL 与抓取时间并提供单条删除入口。
- 验收：见 TC-11。导出文档中检索不到快照正文；批量导入 10 题后快照表为空。

**FR-29 配置驱动的题号链接规则与自动题目录入**（P1，v1.4 新增）

- 描述：所有「题号 → 原题链接」的推导规则集中放在 `config/link_rules.yaml`（用户覆盖层 `config/link_rules.custom.yaml` 可在界面编辑、保存前校验、热加载）。新增站点或修正链接格式**只改 YAML，不改 Python 代码**；自定义来源自动并入可用来源表。
- 规则内容：题号归一化（正则 + 模板）、合法题号 `key_pattern`、URL 模板、URL 反解、全文扫描正则、连续题号范围展开；同一来源可配多个变体（蓝桥云课数字编号 / 旧练习系统 `T1`、`BEGIN-1`）。
- 自动录入：粘贴题号、标题、链接或题单文本 → 按行或全文扫描 → 归一化并生成正确外链 → `dry_run` 预览（含来源识别、查重、规则校验）→ 用户确认后复用 FR-02 事务化导入。混合来源清单自动识别；纯数字题号须指定来源或使用可配的默认来源，避免静默录错。
- 题库体检与修复：按当前规则检查已有题目的题号与链接，列出 `invalid_key` / `url_mismatch` / `missing_url` / `legacy_seed` 并给出建议值；修复需 dry_run 预览 + 二次确认，默认跳过人工编辑过的记录。
- 已核实规则：蓝桥云课 `https://www.lanqiao.cn/problems/{编号}/learning/`（**254 = A+B 问题【OJ 示例题目】**，不是 1）；旧练习系统 `lx.lanqiao.cn/problem.page?gpid={T1|BEGIN-1}`；洛谷 `https://www.luogu.com.cn/problem/{题号}`，P/B/CF/SP/AT/UVA/U/T 前缀，纯数字自动补 P。
- 合规：**只做本地字符串推导与文本扫描，不访问、不抓取、不解析任何题目网页**，不生成题面快照；章节编辑与 FR-04 / NFR-05 / RK-09 的边界不变。
- 验收：见 `docs/03` 第 9 节 —— 33 项测试通过（含规则归一化、URL 反解、范围展开、混合扫描、采集 dry-run/入库、体检修复、自定义来源覆盖层），10 个页面 200，89 题体检 0 问题；规则引擎与采集模块源码中不含任何 HTTP 客户端。

## 附录 C：载体 B 导入契约与单题快照边界（v1.2 新增）

### C.1 会话式导入数据格式

载体 B 依赖「AI 助手产出结构化文件 → 项目按 FR-02 导入」。为避免每次对话临时约定格式，固定以下契约（`schema_version = 1.0`）：

```json
{
  "schema_version": "1.0",
  "generated_at": "2026-11-07T15:30:00+08:00",
  "source_note": "本次由 AI 助手从洛谷搜索整理，共 10 题",
  "problems": [
    {
      "source": "luogu",
      "source_key": "P1001",
      "title": "A+B Problem",
      "url": "https://www.luogu.com.cn/problem/P1001",
      "difficulty_raw": "入门",
      "difficulty_level": 1,
      "external_tags": ["模拟", "数学"],
      "knowledge_nodes": ["基础语法", "模拟"],
      "summary": "考察基本输入输出与加法运算",
      "confidence": "ai",
      "verified": false
    }
  ]
}
```

- 必填：`source`、`source_key`、`title`、`url`；其余可空。
- `(source, source_key)` 去重；`confidence = ai` 的标签与知识点以 `verified = false` 入库，人工确认后才参与组题筛选（FR-06）。
- 导入文件**不含题面原文**；单题快照走 FR-28 单独通道，不混在此文件中。
- 导入前展示预览（新增 / 重复 / 失败各多少条），用户确认后事务写入。

### C.2 FR-28 数据表与补充验收用例 TC-11

- 新增数据表 `problem_snapshots`：`id`、`problem_id`、`content_md`、`source_url`、`captured_at`、`user_initiated`。该表是对第 6 节数据模型的 v1.2 补充。
- 边界：仅**用户主动触发**的**单题**；仅存本地 SQLite；不参与 FR-22 文档导出、不进入对外分享内容、不由批量导入自动生成；界面标注来源 URL 与抓取时间并提供单条删除入口。
- **TC-11 单题快照边界**：对 1 道题保存快照 → 题库详情可见且带来源标注与时间 → 执行 FR-22 导出 → 产物中检索不到快照正文 → 批量导入 10 题 → 快照表仍只有 1 条。
