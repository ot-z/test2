## 3. 关键设计决策

1. **计划快照 + 配置版本化**：`daily_plans.config_snapshot` 保存生成时的全部参数，`daily_plans.config_id` 指向当时的配置版本。参数修改只生成新版本，历史任务数绝不被改写（TC-04）。
2. **复习可追溯**：`daily_plan_items(review).source_plan_item_id` 指回原 new 任务，TC-01 能直接验证「第 8 天复习第 1 天」。生成时按「计划中的新题」预留复习位；若原题后来被 `skipped`，级联把其待办复习项置为 `skipped` 并删除复习状态，保证「跳过不入复习池」。
3. **顺延不堆积**：所有任务在生成时固化，逾期只改状态，不补发任务；暂停/休息日按日历天推进索引，不改变节奏。
4. **快照隔离**：`problem_snapshots` 不在 `SNAPSHOT_MODELS` 中，Markdown/DOCX/PDF 与 JSON 快照都不读取它，TC-11 用唯一标记串做了正文检索断言。
5. **JSON API 优先**：页面只是 `/api` 的消费方，未来换 React 不需要改后端（SRS 3.1）。

## 6. 如何体验（建议顺序）

1. 双击 `启动.bat`，浏览器自动打开首页，看今日任务、健康卡片、题单余量。
2. 点题目外链验证跳转（TC-05）；回来把任务标为「已学题解」，写一条思路笔记并看自动保存。
3. 进「大纲与题单」生成候选题单、剔除两题、调序、确认，再看首页新题队列变化。
4. 进「历史与统计」看统计；进「导出复盘」分别导出 md/docx/pdf 检查中文与代码块。
5. 进「设置」查看计划参数与 AI 配置；**填入撤销重建后的新 Key**，再进「AI 助手」试一次流式分析。
6. 想快速看满数据的效果，可在设置页「载入演示数据」（会清空现有业务数据，需二次确认）；体验完可「重置」恢复初始状态。

## 9. v1.1.0 增量：题号链接规则与自动录入（FR-29）

### 9.1 起因与核实结论

用户反馈「蓝桥杯题目编号有误，A+B 题号不是 1，链接不对」。核实结果：

- 蓝桥云课官方题库列表页使用「编号」作为题号，**A+B 问题【OJ 示例题目】= 254**，链接 `https://www.lanqiao.cn/problems/254/learning/`（做题需登录蓝桥账号，重定向到 passport 属正常）；v1.0.0 起始题库里 `1`~`6` 是虚构编号。
- 旧版练习系统用 `gpid`：入门训练 A+B 是 `T1` / `BEGIN-1`，对应 `lx.lanqiao.cn/problem.page?gpid=...`。
- 洛谷题号有前缀体系：P（主题库，纯数字可省略 P 自动补）、B、CF、SP、AT、UVA、U、T（后两者为 4~8 位数字）；蓝桥杯历年真题在洛谷也是 P 开头（P8649、P16232 等）。

## 10. v1.1.1 增量：修复「生成任务计划点了没反应」

### 10.1 现象与根因

用户截图反馈首页「重新生成 30 天计划」不生效：今日仍只有 1 项已跳过的任务。实测 `POST /api/plan/generate?days=30` 返回 `generated_plans: 0 / generated_items: 0`。三个叠加原因：

1. `plan.generate()` 的窗口固定从配置的 `start_date` 起算。用户把起始日期改到 `2026-10-24` 后，30 天窗口变成 `10-24 ~ 11-22`，其中 14 天是过去，且库里已有 44 天计划（`10-24 ~ 12-06`），整段窗口全部命中幂等跳过；
2. `generate()` 对已存在的日期是「整日跳过」，不是「补足缺口」。用户把每日新题从 1 改成 3 后，已有日期仍是 1 项，改参数对计划没有任何可见效果；
3. 前端按钮叫「重新生成」，但实际调用的是幂等 `generate`，产品语义与实现不一致，且返回值 0 时只弹一句「已生成 0 天 / 0 项任务」，没有任何解释。

### 10.2 实现清单

| 层 | 文件 | 内容 |
| --- | --- | --- |
| 服务 | `app/services/plan.py` | 新增 `regenerate()`：窗口从今天起算，已存在日期按当前配置补齐 new / review 任务缺口，不删除、不改任何已有任务；仍遵守 FR-10（队列耗尽只标记「题单不足」，不从题库随机补题）；补齐后再次调用不产生重复任务 |
| 服务 | `app/services/plan.py` | 新增 `refill_queue()`：用户显式点击后，把「未进激活题单、也未出现在任何计划任务」的题追加进题单，补了哪些题、覆盖多少天都在返回里可见；不改计划参数 |
| 接口 | `app/api/routes_plan.py` | `POST /api/plan/regenerate?days=N`（可选 `from_date`）、`POST /api/plan/refill-queue`；`/api/plan/generate` 增加可选 `from_date`，**默认幂等语义不变**（TC-01～TC-04 保持通过） |
| 界面 | `app/web/templates/today.html` | 按钮改为「重建未来 30 天计划」+ 新增「只补今天」；结果区显示窗口、补齐任务数、容量估算与题单不足告警；题单不足时提供「从题库补充题单并重建」，以及去大纲题单 / 题号采集 / 设置的引导链接 |
| 界面 | `app/web/templates/settings.html` | 保存计划参数后明确提示「须回首页点重建未来计划才对未来生效」 |

**兼容性**：TC-04「参数变更不回溯」仍成立——单纯改配置不会自动改历史计划，只有用户显式调用重建才按新参数补齐未来；`config_snapshot` 保持不变。

### 10.3 真实数据修复

先备份 `backups/quiz-pre-regenerate-20261107-173910.db`，恢复后按「补充题单 → 重建」顺序执行：题库 89 道中补入 16 道未排过的题（队列 29 → 45），再按当前配置（每日 3 新题 + 3 复习）重建 `2026-11-07 ~ 12-06`。今日由 1 项已跳过变为 **4 项**（1 已跳过 + 2 新题 + 1 复习，其中 3 项可做），重建后再调用返回 0 项（幂等）。
